Setup Runbook

Getting kerph.com live

A step-by-step path from "code on my laptop" to "a real website at kerph.com." Written for zero prior experience — every click is spelled out.

Total cost
~$12/yr
Hands-on time
~25 min
Accounts needed
3 free/cheap
Part 1Buy the domain

A domain is just a rental — you're leasing the right to the name "kerph.com" for a year at a time, from a company called a registrar.

1
Create a Namecheap account and search for the domain

Go to namecheap.com. In the big search bar on the homepage, type kerph.com and hit search.

If it shows up available, click Add to Cart, then create a free Namecheap account when prompted (email + password is enough).

If kerph.com is taken: don't panic — try kerphapp.com, getkerph.com, or the newer kerph.app / kerph.io extensions. .com is the most recognizable, but not required.
2
Check out — and skip the upsells

At checkout, Namecheap will offer you a stack of extras: SEO tools, email hosting, a website builder, "PremiumDNS." You need none of it — click past each one.

Do keep domain privacy (sometimes called WhoisGuard) turned on — it's usually free and hides your home address from the public domain registry.

Expect to pay around $10–15 for the first year. Renewal price is similar — domains auto-renew by default, so keep the card on file current or you can lose the name.
Part 2Put the code somewhere the internet can reach

Right now Kerph only exists as files on your computer. We'll push it to GitHub (a free code backup/host), then connect a hosting service that watches GitHub and republishes automatically every time it changes.

3
Create a GitHub account and a new repository

Go to github.com and sign up (free). Once in, click the + in the top right → New repository.

  • Name it kerph-app
  • Set it to Private (you can make it public later — no rush)
  • Leave everything else unchecked, click Create repository
4
Push your local project up to it

GitHub shows you a page of setup commands right after creating the repo — but here's exactly what to run (tell me and I'll run it with you when you're ready):

git remote add origin https://github.com/YOUR-USERNAME/kerph-app.git
git branch -M main
git push -u origin main

The first push will pop up a browser window asking you to sign in to GitHub — that's normal, just approve it.

Prefer clicking over typing? GitHub Desktop (desktop.github.com) does the same thing with buttons instead of commands.
Part 3Host it live

We'll use Netlify — free for a site this size, built for exactly this kind of plain HTML/CSS/JS project, and it auto-publishes every time GitHub changes.

5
Sign up and connect the repository

Go to netlify.com → Sign up → choose Sign up with GitHub (links the two accounts, no extra password).

On the dashboard: Add new site → Import an existing project → GitHub → pick kerph-app from the list.

On the settings screen that follows, leave Build command empty and Publish directory empty (or a single /) — the site has no build step, it's ready to serve as-is. Click Deploy.

6
Confirm the test URL works

Within about a minute, Netlify hands you a URL like glowing-narwhal-4821.netlify.app. Open it — you should see the real Kerph home page. This confirms hosting works before we touch the domain at all.

Part 4Point kerph.com at it

This is the step that actually makes kerph.com show your site instead of a "domain parked" page.

7
Add the domain in Netlify

In your Netlify site → Site configuration → Domain management → Add a domain → type kerph.com → confirm. Netlify will offer to set up Netlify DNS for you — accept it. It'll show you two nameserver addresses, something like:

dns1.p05.nsone.net
dns2.p05.nsone.net
8
Hand DNS control to Netlify, back in Namecheap

Back in Namecheap: Domain List → Manage (next to kerph.com) → Nameservers → switch the dropdown to Custom DNS → paste in the two addresses Netlify gave you → save (the checkmark).

This is the one step with a wait. DNS changes can take anywhere from a few minutes to about 48 hours to fully spread across the internet — usually it's under an hour. Netlify's domain page will show a green check once it sees the change.
9
Verify it's live, over HTTPS

Netlify automatically issues a free HTTPS certificate once DNS verifies — no action needed from you. Open an incognito/private window and visit https://kerph.com. You should see the site, with a padlock in the address bar.

Part 5Going forward

This is the part that matters every day after setup — how a change we make together actually reaches kerph.com.

10
The update loop, from now on

Once this is wired up, publishing an update is just: we finish work in a session → I commit and push it to GitHub with your OK → Netlify notices within seconds and rebuilds → kerph.com updates automatically, usually inside a minute. You never manually upload anything again.

You can watch it happen in Netlify's Deploys tab any time — every push shows up there with a status and a timestamp.

A few things worth knowing

  • www vs. bare domain — once kerph.com is connected, Netlify lets you pick whether kerph.com or www.kerph.com is the "primary" address; it auto-redirects the other one to match, so nobody hits a broken link either way.
  • Renewals — mark the domain's renewal date somewhere you'll see it. Losing it to an expired card is the single most common way people accidentally lose a domain.
  • Backend later — none of this changes if/when Supabase gets wired in for real accounts; Netlify happily serves a site that talks to an external backend, that's a separate, later step.
